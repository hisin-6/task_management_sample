# 要件定義

## 1. 目的

個人のタスクを登録・管理し、期限や進捗を把握できるようにする。
カテゴリでタスクを分類し、目的のタスクをすぐに探せるようにする。

## 2. 利用者

- 一般ユーザー（ログインして自分のタスクを管理する）

管理者機能は作らない。ユーザーは自分のデータだけを扱う。

## 3. 機能要件

| No | 機能 | 概要 | 優先度 |
| --- | --- | --- | --- |
| F-01 | ユーザー登録 | ユーザー名とパスワードでアカウントを作成 | 必須 |
| F-02 | ログイン / ログアウト | 登録済みのユーザー名とパスワードで認証 | 必須 |
| F-03 | タスク一覧 | 自分のタスクを一覧表示（削除済みは表示しない） | 必須 |
| F-04 | タスク詳細 | タスクの全項目を表示 | 必須 |
| F-05 | タスク登録 | 下記「4. タスクの項目」を入力して登録 | 必須 |
| F-06 | タスク編集 | 登録内容を変更 | 必須 |
| F-07 | タスク削除 | 論理削除（DBには残し、画面から見えなくする） | 必須 |
| F-08 | ステータス変更 | 未着手 / 進行中 / 完了を切り替え。完了にすると完了日時を記録 | 必須 |
| F-09 | カテゴリ管理 | カテゴリの一覧・登録・名前変更・削除 | 必須 |
| F-10 | 検索・絞り込み | キーワード・ステータス・カテゴリ・期限で絞り込み | 任意 |
| F-11 | 並び替え・ページング | 期限・優先度・登録日時で並び替え、1ページ10件で表示 | 任意 |

## 4. タスクの項目

| 項目 | 必須 | 入力ルール | 備考 |
| --- | --- | --- | --- |
| タイトル | ○ | 1〜100文字 | |
| 詳細 | | 1000文字以内 | |
| 期限 | | 日付 | 時刻は持たない |
| 優先度 | ○ | 高 / 中 / 低 | 初期値は「中」 |
| ステータス | ○ | 未着手 / 進行中 / 完了 | 初期値は「未着手」 |
| カテゴリ | | 自分のカテゴリから1つ選択 | 未分類も可 |
| 完了日時 | | 画面からは入力しない | ステータスに連動して自動で設定 |

### 業務ルール

- ステータスを「完了」にしたとき、完了日時に現在日時を記録する
- 「完了」から別のステータスに戻したとき、完了日時を空にする
- カテゴリを削除したとき、そのカテゴリのタスクは「未分類」になる（タスクは消さない）
- カテゴリ名は、同じユーザーの中で重複できない

## 5. 非機能要件

### セキュリティ

- パスワードはBCryptでハッシュ化して保存する
- 他ユーザーのタスク・カテゴリは参照も操作もできない（URLを直接入力した場合は404を返す）
- フォーム送信はCSRF対策を行う（Spring Securityの標準機能を使う）
- ログインしていない状態でログイン画面とユーザー登録画面以外にアクセスしたら、ログイン画面へ移動する

### その他

- 入力エラーがあった場合は、入力内容を残したまま画面にエラーメッセージを表示する
- 想定外のエラーが起きた場合は、共通のエラー画面を表示する
- 動作環境はPCのブラウザ（Chrome最新版）を想定する

## 6. 対象外とするもの

1か月で作り切るため、次の機能は今回は作らない。

- タグ機能（1つのタスクに複数のラベルを付ける機能）
- パスワードの再設定、メールアドレスでの認証
- タスクの共有、複数人での共同編集
- 削除したタスクの復元画面（論理削除なのでDBには残る）
- スマホ向けのレイアウト調整
